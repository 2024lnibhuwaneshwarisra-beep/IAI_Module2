Concept 3 · Learn, then quiz

The three types of prompts

The book names three types of prompts. Read the three cards, then take the graded quiz.

1. Natural-language promptsWhat it is: instructions written the way people talk, giving the model clues in ordinary language, so you can work with it naturally.
Looks like: “Explain what a diode does in two sentences.”
2. System promptsWhat it is: ready-made guidelines or templates that a developer supplies to steer the model's output, stating clearly the behaviour or format expected.
Looks like: “You are a lab assistant. Always answer in bullet points.”
Tutorial link: the system prompt box in Ch. 1 and Ex 1.2.
3. Conditional promptsWhat it is: prompts that put the model under particular limits or contexts, using statements like “If X, then Y” or “Given A, generate B”.
Looks like: “If there are more than 3 resistors, show the steps.”
Tutorial link: the “if you are unsure, say…” rules in Ch. 9 and the “give Claude an out” idea in Ch. 8.

Memory trick: natural = how you speak. System = standing rules. Conditional = if or given. Real prompts often mix types.

Theory

How prompt engineering works: the five principles

Open each part to read a full explanation of how prompt engineering works and its five guiding principles.

Memory trick: U-P-D-E-E = Understand, Precise, Details, Examples, Experiment. Draw this cycle in your notes.

Introduction

Prompt engineering is the process of designing and refining the instructions (prompts) given to a large language model (LLM) so that it produces the output we want. The process is intricate and recursive: there is no one-size-fits-all method, and the best approach depends on the particular LLM and the task. Engineers therefore follow five broad principles.

Principle 1: Understand the task thoroughly

Explain: Before writing anything, decide what you expect from the LLM and what kind of result you want: an answer, a summary, code, a table? Only when the assignment is clear can you design a prompt that helps the model reach your objective.

Why it matters: Without a clear goal the model has to guess the task, the audience and the format.

Example: Goal unclear: “Tell me about circuits.” Goal clear (exam revision): “Write revision notes on series and parallel circuits for a first-year exam.”

Class link: Tutorial Ch. 2, clear and direct.

Principle 2: Make your wording precise and succinct

Explain: Leave no doubt about what you are asking. Use straightforward language, keep it short, and avoid jargon.

Why it matters: The model only has your words, so vague words give vague output.

Example: Vague: “Make it short and good.” Precise: “Summarise in 3 bullet points, under 60 words.”

Class link: Tutorial Ex 2.2, one player only.

Principle 3: Give details

Explain: The more specific the prompt, the more likely the response is relevant and informative. The textbook's own example: instead of “write a poem”, ask for “a poem about a lost love”.

What details to add: topic, audience, length, format and tone.

Example: “Explain Ohm's law.” becomes “Explain Ohm's law to a first-year student using a 12 V battery and a 4 Ω resistor, in 3 steps.”

Class link: Tutorial Ch. 3 and Ch. 4, roles and clear inputs.

Principle 4: Give instances, i.e. examples

Explain: Where possible, show the LLM samples of the output you want. This helps it understand your goal and gives more accurate results. This idea leads to one-shot and few-shot prompting (Unit 2.3).

Example: “Convert device names to lab codes. Lamp → LP-1. Fan → FN-2. Motor →” (the model copies the pattern and answers MT-3).

Class link: Tutorial Ch. 7, few-shot.

Principle 5: Try things out, i.e. experiment

Explain: Prompt engineering cannot be done in one fixed way. Try different prompts, look at the results, and refine. What works for one LLM or one task may not work for another.

Example: Run prompt v1, notice the answer is too long, add “under 80 words”, run again as v2. Keep both in your Prompt Portfolio and note why v2 is better.

Class link: Every tutorial exercise, and your Prompt Portfolio.

Example and conclusion

Worked example: v1 “Explain transistors.” → v2 “Explain what a transistor does to a first-year engineering student. Use exactly 3 bullet points, each with one real device example. Keep it under 80 words.” Each added phrase applies one principle.

Conclusion: Together the principles move a prompt from vague to precise: understand the task, word it precisely, add details, show examples, then test and refine. Because the process is recursive, the cycle repeats until the output meets the goal. Well-engineered prompts give more accurate, relevant and creative results, which is why the skill matters in communication, coding, writing and research.
